About These Notes

This page is a collection of my bioinformatics learning notes. I have documented concepts, tools, commands, and workflows in the way I understood them while learning. I hope these notes help others who are beginning their journey in bioinformatics.

All information related to databases, file formats, sequencing data, and other relevant background concepts is introduced step by step as it becomes needed during the learning and analysis process.

Where Does Bioinformatics Begin?

Suppose you have collected a biological sample, such as blood, plant tissue, bacteria, or honey bees, and sent it for DNA or RNA sequencing.

Sequencing is a laboratory process that determines the order of nucleotides in DNA or RNA. In simple terms, sequencing reads the genetic information present in a sample and converts it into digital data that can be analyzed on a computer.

After sequencing is completed, the sequencing facility usually provides data files called FASTQ files.

A FASTQ file is a text file that stores raw DNA/RNA sequencing data generated by a sequencing machine. It contains millions of short sequences, along with a quality score for each nucleotide. The name FASTQ comes from the FASTA format combined with quality (Q) scores.

At this point, a common question is:

Why do we get millions of short sequences instead of one complete DNA sequence?

The reason is that most sequencing machines cannot read very long DNA molecules in a single step. Instead, they break the DNA or RNA into many smaller fragments and sequence each fragment separately. The machine can read these smaller pieces accurately and quickly. As a result, the output consists of millions of short sequences rather than a few very long ones.

Each of these short sequences is called a read.

For example, a sequencing machine might produce reads such as:

ATCGGCTAAGT...
GGCTATCGTTA...
TTAACCGGTAA...

Each read represents a small piece of the original DNA or RNA sample.

A quality score is a numerical value assigned to each nucleotide in a read. It tells us how confident the sequencing machine is that a particular base was identified correctly. Higher quality scores indicate higher confidence, while lower scores suggest a greater chance of sequencing errors.

To better understand what a FASTQ file looks like, imagine opening one in a text editor. You might see something similar to the example below: 

@SRR123456.1
ATCGGCTAAGTCGATCGATC
+
IIHGFEDCBA!!!??>>><<

This represents a single read. The first line is the read identifier, the second line is the nucleotide sequence, the third line is a separator, and the fourth line contains the quality scores.

At this stage, we have the raw sequencing data in FASTQ files. The file contains all the sequence information, but simply having the data does not immediately answer our biological questions. Although the FASTQ file contains the information needed to answer these questions, the answers are not directly visible. The file is simply a collection of millions of short reads and quality scores.

Before we can perform any biological analysis, we first need to understand and process these files.

This presents another challenge.

FASTQ files are often very large, sometimes containing millions of reads and occupying several gigabytes of storage. While it is possible to open a FASTQ file with a text editor, doing so is usually not practical because the file can contain millions of lines of data. Simply scrolling through the file does not tell us anything useful about the biology of the sample.

What we need is a way to organize, inspect, filter, and process this raw sequencing data into a form that can be analyzed and interpreted.

At this stage, Linux becomes an essential platform for handling sequencing data.

Linux provides the environment in which most bioinformatics tools are run. Using Linux, we can efficiently work with large sequencing files, examine their contents, assess data quality, remove low-quality reads, align sequences, quantify gene expression, and perform many other analyses.

The output of these bioinformatics tools is often much easier to interpret than the original FASTQ file. Instead of millions of raw reads, we eventually obtain summaries, counts, tables, and other results that can be used for statistical analysis and biological interpretation.

So the next step is to move into the Linux environment and start working with these files directly.

Linux for Bioinformatics

Linux is an operating system just like Windows or Mac. It sits between the computer hardware and the user, helping us manage files, run programs, and use system resources like storage, memory, and processor.

In bioinformatics, sequencing data such as FASTQ files are very large. One FASTQ file can be around 30 GB. In real research, we usually have multiple samples from different treatments and replications, so the total data can easily reach hundreds of GB.

To permanently store this data, we need enough storage.
While working with it temporarily, we need enough RAM.
To execute instructions and handle all computations, we need a powerful processor (CPU).

For small datasets, a normal laptop (storage, RAM, and CPU) is enough. But for large biological datasets, we need external systems that provide high storage capacity, large RAM, and many processors. These systems are called High-Performance Computing (HPC) systems or supercomputers.

To manage and work with these large FASTQ files—whether on a laptop or on an HPC system—we use a command-line environment. Instead of clicking and opening files like in a normal graphical interface, we interact with the system using simple text-based commands.

These commands allow us to access and view files, move and organize data, download large sequencing datasets, and perform basic operations. The system executes these commands and returns the output. So, file handling and data operations are done through direct command-based interaction in a text environment.

Working With FASTQ Files

Now we have the FASTQ files, which contain raw sequencing reads, and we are working in a Linux environment where we have already learned some basic commands to handle files.

Next question naturally comes: what are we going to do with this data?

The FASTQ data we get directly from sequencing — is it already good enough for downstream analysis?

In most cases, the answer is no. Before using it, we first need to check its quality.

To understand why, it helps to know what actually happens during sequencing.

Before sequencing, DNA goes through a step called library preparation, where the DNA is broken into small fragments. Then, two short artificial DNA sequences called adapters are attached — one at the 5′ end and another at the 3′ end of each fragment. These adapters are important because they serve as binding and recognition sites for the sequencing machine.

They also define the direction of sequencing. Since the adapters are known sequences, they allow the fragment to attach to the sequencing flow cell and initiate the sequencing reaction in a controlled orientation, depending on the library type.

During sequencing, machines such as Illumina systems read these fragments in short stretches called reads, usually around 100–150 nucleotides in length. Each read is stored in a FASTQ file along with a quality score for every base, which represents how confident the machine is about each nucleotide call.

However, sequencing is not perfect. The accuracy is not constant across the entire read. At the beginning of the read, the quality is usually high, but as sequencing progresses toward the end, the signal becomes weaker and the error rate increases. So the later part of the read is more likely to contain incorrect bases.

Another common issue is adapter contamination. Although adapters are necessary during library preparation to attach fragments to the sequencing system, they are not part of the real biological DNA. If the original DNA fragment is shorter than the read length, the sequencing machine continues reading beyond the actual DNA insert and enters the adapter region. Because these adapter sequences are artificial, they can appear in our FASTQ files and must be removed.

So in simple terms, raw FASTQ files can contain:

sequencing errors (mainly low-quality bases toward the end of reads)
adapter contamination (non-biological sequences from library preparation)

Phred Quality Score (ASCII Encoding Table)

In FASTQ files, quality scores are not written as numbers. Instead, they are encoded using ASCII characters. Each symbol represents a specific Phred quality score.

In total, there are many ASCII symbols used in FASTQ quality encoding (depending on the encoding system, usually representing Phred scores from 0 up to around 40 in real Illumina data, and theoretically even higher). However, in practice, we only commonly see a limited range in real sequencing datasets.

Below is a small example of commonly observed symbols and their corresponding Phred quality scores:

ASCII Symbol Phred Score (Q) Interpretation
! 0 Very bad quality
" 1 Very bad quality
# 2 Very low quality
$ 3 Very low quality
% 4 Poor quality
& 5 Poor quality
' 10 Low quality (borderline usable)
+ 20 Moderate quality (acceptable in many analyses)
5 30 High quality (good confidence)
I 40 Very high quality (excellent confidence)

What Quality is Good or Bad?

  • Q ≥ 30 → High quality reads (generally considered very reliable)
  • Q ≥ 20 → Acceptable quality (used in many standard analyses)
  • Q < 20 → Low quality (needs caution)
  • Q < 10 → Very poor quality (should be trimmed or removed)

Because of these issues, raw data cannot be directly trusted for analysis. If we use it without processing, it can lead to incorrect alignments and misleading biological results.

That is why the first step after receiving FASTQ files is quality control (QC), which means checking how good the sequencing data is. This gives us a clear idea of whether the data is usable or needs cleaning.

Based on this QC report, we perform a step called trimming, where we remove low-quality bases and adapter sequences from the reads.

After this cleaning step, we obtain high-quality sequencing data that is reliable and ready for downstream analysis.
