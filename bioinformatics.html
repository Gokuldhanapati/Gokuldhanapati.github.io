About these notes

This page is a collection of my bioinformatics learning notes. I have documented concepts, tools, commands and workflows in the way I understood them while learning. I hope they help others who are starting out in bioinformatics with a foundation in molecular biology.

Databases, file formats, sequencing data and other background concepts are introduced step by step, as they become needed during the analysis.

Where does bioinformatics begin?

Suppose you have collected a biological sample, such as blood, plant tissue, bacteria or honey bees, and sent it for DNA or RNA sequencing.

Sequencing is a laboratory process that determines the order of nucleotides in DNA or RNA. In simple terms, it reads the genetic information in a sample and converts it into digital data that can be analysed on a computer.

After sequencing, the facility usually provides data files called FASTQ files.

A FASTQ file is a text file that stores raw DNA/RNA sequencing data generated by a sequencing machine. It contains millions of short sequences, along with a quality score for each nucleotide. The name comes from the FASTA format combined with quality (Q) scores.

Why millions of short sequences instead of one complete sequence?

Most sequencing machines cannot read very long DNA molecules in a single step. Instead, they break the DNA or RNA into many smaller fragments and sequence each fragment separately, which they can do accurately and quickly. The output is therefore millions of short sequences rather than a few very long ones.

Each of these short sequences is called a read. A sequencing machine might produce reads such as:

ATCGGCTAAGT...
GGCTATCGTTA...
TTAACCGGTAA...

Each read represents a small piece of the original DNA or RNA sample.

A quality score is a number assigned to each nucleotide in a read. It tells us how confident the machine is that the base was identified correctly. Higher scores mean higher confidence; lower scores suggest a greater chance of error.

If you open a FASTQ file in a text editor, a single read looks like this:

@SRR123456.1
ATCGGCTAAGTCGATCGATC
+
IIHGFEDCBA!!!??>>><<

The first line is the read identifier, the second is the nucleotide sequence, the third is a separator and the fourth holds the quality scores.

At this stage we have the raw data, but simply having it does not answer our biological questions. The answers are in the file, but they are not directly visible: it is just a collection of millions of short reads and quality scores. Before any biological analysis, we need to understand and process these files.

That brings another challenge. FASTQ files are often very large, with millions of reads and several gigabytes of storage. You can open one in a text editor, but scrolling through millions of lines tells us nothing useful about the biology of the sample.

What we need is a way to organise, inspect, filter and process raw sequencing data into a form that can be analysed and interpreted. This is where Linux becomes essential.

Linux provides the environment in which most bioinformatics tools run. With it we can work efficiently with large sequencing files, examine their contents, assess quality, remove low-quality reads, align sequences, quantify gene expression and much more. The outputs, such as summaries, counts and tables, are far easier to interpret than the original FASTQ file and can be used for statistical analysis and biological interpretation.

So the next step is to move into the Linux environment and start working with these files directly.

Linux for bioinformatics

Linux is an operating system, just like Windows or macOS. It sits between the computer hardware and the user, helping us manage files, run programs and use resources like storage, memory and the processor.

In bioinformatics, sequencing data are very large. One FASTQ file can be around 30 GB, and real studies usually have several samples across treatments and replications, so the total can easily reach hundreds of gigabytes.

  • To store this data permanently, we need enough storage.
  • To work with it temporarily, we need enough RAM.
  • To run instructions and computations, we need a powerful processor (CPU).

For small datasets, a normal laptop is enough. For large biological datasets, we need systems with high storage, large RAM and many processors. These are called High-Performance Computing (HPC) systems, or supercomputers.

What software should I use?

If you work mainly on your own computer, Ubuntu is a good choice because it gives you a Linux environment for running bioinformatics commands. Download Ubuntu.

If you have access to an HPC, your data and analyses usually live there rather than on your laptop. MobaXterm lets you connect from your laptop to the HPC and run Linux commands remotely. Download MobaXterm.

The software may differ, but the Linux commands are generally the same.

Whether on a laptop or an HPC, we work with these large files through a command line. Instead of clicking and opening files, we type simple text commands to view files, move and organise data, download large datasets and run tools. The system executes each command and returns the output.

Working with FASTQ files

We now have the FASTQ files and know some basic Linux commands. Can we use these reads directly for downstream analysis? In most cases, no. First we need to evaluate their quality.

Each base in a FASTQ file has a quality score reflecting how confident the machine was. Modern sequencing is highly accurate, but raw data are rarely perfect: several factors during sequencing can introduce errors or unwanted sequences. Quality control (QC) is therefore the essential first step.

Why is quality control necessary?

Before sequencing, DNA molecules go through library preparation, during which short artificial DNA sequences called adapters are attached to both ends of each fragment. Adapters let the sequencing machine recognise and sequence the fragments. Two common problems then show up in raw data:

1. Low-quality bases

Accuracy is usually highest at the start of a read and decreases toward the end, so the later part of a read is more likely to contain incorrect base calls.

2. Adapter contamination

If a DNA fragment is shorter than the read length, the machine keeps reading past the actual DNA insert into the adapter itself. Adapters are artificial and not part of the sample, so they must be removed.

Using such data without cleaning can lead to incorrect alignments and inaccurate biological conclusions.

Quality control with FastQC

QC gives an overview of the sequencing run and helps identify problems such as low-quality bases and adapter contamination. FastQC is one of the most widely used tools for this.

Trimming with fastp

Based on the QC results, we run trimming: low-quality regions and adapter sequences are removed from the reads. The cleaner data are then suitable for downstream analyses such as read alignment, genome assembly and variant detection. fastp removes low-quality bases and adapters in one step.
